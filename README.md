# Orderbook API

An order book API built with FastAPI. It supports placing and cancelling limit
buy and sell orders, and querying orders, trades, and the order book.

The project uses a single order book with no symbol distinction. Data is stored
in memory for the lifetime of the process.

## Installation

From the project root, using Python 3.14 (the version used for testing):

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Dependencies are pinned in [requirements.txt](requirements.txt), including
`httpx` for HTTP tests.

## Running the API

```sh
.venv/bin/python -m uvicorn app.main:app --reload
```

The API is available at `http://127.0.0.1:8000`:

- [Swagger UI](http://127.0.0.1:8000/docs)
- [ReDoc](http://127.0.0.1:8000/redoc)
- [OpenAPI schema](http://127.0.0.1:8000/openapi.json)

Reloading or restarting the server resets all data. Use a single worker:
multiple processes would each have their own storage and order book.

## Routes

| Method | Route | Description |
| --- | --- | --- |
| GET | `/orders` | List all orders, including filled and cancelled orders |
| GET | `/orders/{order_id}` | Retrieve an order |
| POST | `/orders` | Place a limit order and run matching |
| PATCH | `/orders/{order_id}` | Cancel an open or partially filled order; no request body required |
| GET | `/trades` | List trades generated by matching |
| GET | `/trades/{trade_id}` | Retrieve a trade |
| GET | `/orderbook` | Retrieve active orders grouped by price in `bids` and `asks` |
| GET | `/health` | Return `{"status": "ok"}` |

Successful responses use status code `200`, including order creation.
Errors use the format `{"detail": ...}`:

- `404`: order or trade not found.
- `409`: attempt to cancel an order that is already filled or cancelled.
- `422`: invalid request, including a price or quantity that is not strictly
  positive, a side other than `buy`/`sell`, or a non-integer identifier.

## Example

Starting with empty storage, place a sell order for 5 units at a price of 100:

```sh
curl -X POST http://127.0.0.1:8000/orders \
  -H 'Content-Type: application/json' \
  -d '{"side": "sell", "price": "100", "quantity": "5"}'
```

Then buy 2 units with a limit price of 101:

```sh
curl -X POST http://127.0.0.1:8000/orders \
  -H 'Content-Type: application/json' \
  -d '{"side": "buy", "price": "101", "quantity": "2"}'
```

The buy order is fully filled at the resting sell order's price: 100.
The sell order retains 3 units and changes to `partially_filled`.

```sh
curl http://127.0.0.1:8000/orders/1
curl http://127.0.0.1:8000/trades
curl http://127.0.0.1:8000/orderbook
```

Cancel the remaining quantity of the sell order:

```sh
curl -X PATCH http://127.0.0.1:8000/orders/1
```

The sell order changes to `cancelled` and leaves the book; the completed trade
remains available. Cancelling the same order again returns `409`.

## Matching rules

- A buy order matches sell orders at the best available price, while their price
  is less than or equal to its limit.
- A sell order matches buy orders at the best available price, while their price
  is greater than or equal to its limit.
- Orders at the same price are filled in arrival order (FIFO).
- Each trade uses the price of the order already resting in the book.
- Any unfilled quantity is added to the book.

Prices and quantities use `Decimal`. Decimal values are returned as JSON
strings, and price level keys are also strings. `quantity` is the original
quantity; `remaining_quantity` is the unfilled quantity. After cancellation,
that remaining quantity records the amount cancelled.

Possible statuses are `open`, `partially_filled`, `filled`, and `cancelled`.

## Project structure

```text
app/
  api/           # Routes for orders, trades, and the order book
  models/        # Domain models and matching engine
  schemas/       # HTTP validation and serialization
  services/      # Operations on orders, trades, and the order book
  storage/       # In-memory storage, counters, and lock
  dependencies.py
  exceptions.py
  main.py        # Application, lifespan, and health route
tests/
  unit/          # Service and matching tests, grouped by module
  http/          # Route tests, grouped by module
requirements.txt # Pinned application and test dependencies
```

The `lifespan` creates storage shared by all three services. Routes retrieve
these services through FastAPI dependencies. Order creation and cancellation
use the storage lock.

## Tests

No server needs to be started: HTTP tests use `TestClient` with the real
lifespan and fresh storage for each test.

```sh
# Full suite
.venv/bin/python -B -m unittest discover -s tests -t . -v

# Unit tests only
.venv/bin/python -B -m unittest discover -s tests/unit -t . -v

# HTTP tests only
.venv/bin/python -B -m unittest discover -s tests/http -t . -v

# One module: replace orders with trades or orderbook as needed
.venv/bin/python -B -m unittest discover -s tests/unit/orders -t . -v
.venv/bin/python -B -m unittest discover -s tests/http/orders -t . -v
```

Tests follow route order and can be run independently.
See the [test documentation](tests/README.md) for details.
